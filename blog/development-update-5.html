Introduction

It has been a slower month for Kova this November, primarily because my personal commitments to study and work have been quite high. That, and Kova itself is settling into quite a stable form, where most updates going forward are feature additions more than bug fixes. I have now fully integrated Pele into Kova, where it serves as the main renderer for diagrams, with Mermaid still in place as a fallback for any unsupported diagrams or for users who prefer its appearance. Most of the time I have spent on Kova in November has gone into a codebase-wide refactor, discussed in a bit more depth below.

Roadmap Items

November Refactor

Some users have likely noticed the large number of branches that have appeared on the repository, all feeding into the main 1126-refactor branch. This is part of a full codebase refactor that is being powered primarily by AI agents under strict instruction. I want to talk a bit more about what this means, as there has been a significant change in the structure of the codebase (though the functionality is identical), as well as about my process for working with AI tooling.

As of 0.8.4, the codebase is not the cleanest. It was a project started with some basic aims of what I wanted to achieve personally, and it rapidly grew with the wonderful suggestions and contributions from the community, bringing in a large quantity of new features in a short space of time. My process has always been, and will continue to be, focused on developing a base for features and having AI support with the full implementation. I then review the completed code before merging it into the main branch. The core issue that 1126-refactor is addressing is the size of the src/App.tsx file. At the time of writing it is 3,415 lines of code in main; the 1126-refactor version is 1,414 lines, with more to come out.

What is happening is proper modularisation of the codebase. Those who have been watching will also have seen numerous new, smaller files. This is where functionality has been taken out of App.tsx and moved into its own file, making reading and maintaining the code far, far quicker and easier. For example, App.tsx previously contained resolveCliTheme, which handles the theme functionality of the CLI tool. It now lives in its own CLI-specific folder, at src/cli/coldStart.ts. The aim is for App.tsx to become the main “wiring panel”, so to speak, for all of the individual components of Kova.

This is handled by AI agents and sub-agents that are tasked with refactoring the codebase using the DRY, TDD and SOLID principles of software development. The agents write tests for the functionality currently present in App.tsx, then create a modularised replacement for that code in an independent file. This allows for focused, standalone testing and review. Once a piece has been compartmentalised, all affected and migrated functionality is fully tested in a local development build of Kova before it is brought into main.

Localisation Plans

Kova is currently available in two languages with complete translations: English and German (provided by a1880). In an earlier development update, I explained that I felt translations should remain in the hands of the communities that need them, and not be handed off to a translation platform and pushed without review. I have been looking into more language options and would like to grow Kova’s localisations, and there are several options for achieving this through LLMs. I would like to open this up to the community to share their thoughts on the matter. Please share your thoughts on issue #346.

Next Steps

Work on the refactor will continue, with the first batch of changes due to land in main in the next week or so, once I have finished testing the current contents of the 1126-refactor branch. These should be included in the 0.8.5 release in a couple of weeks’ time.

I will also be preparing a first localisation file for the 0.8.5 release. I will put more detail into the request for community comment on which language to translate through automated methods. It is important to me that we have users of that language who can properly review the accuracy of the translations. I hope this will also allow users to make a more informed choice on whether they are “for” or “against” automated localisation of Kova.

Thanks

Thanks as always to the community for your continued feedback. Your feedback and support drive Kova’s development and keep the project accountable. Please keep the feedback and questions coming; they keep me thinking about development choices and the direction Kova takes from here.
